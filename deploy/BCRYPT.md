# bcryptjs 3.0.3 — 2026-11-15

Official npm bcryptjs 3.0.3 replaces 2.4.3. No application password policy,
JWT settings, database schema, or existing stored hashes are changed. The
registry keeps cost 10 and TessTOC keeps cost 12. New hashes use the upstream
2b prefix; existing 2a hashes remain valid. Built-in TypeScript types replace
TessTOC's old @types/bcryptjs package. No new dependencies are added.

Synthetic fixtures were generated by the previously installed official 2.4.3.
Unit checks cover 2a/2b/2y, wrong passwords, Cyrillic/Unicode, NUL, and the
72-byte UTF-8 boundary including existing long-password behavior. New salts
must differ, new hashes must preserve each app's work factor. Local rollback
checks also verify that 2.4.3 accepts new 3.0.3 hashes. Fixtures are not customer
passwords or hashes; the previous library itself is not added to dependencies.

CI-only API checks require the disposable localhost database on port 5432,
CI=true and the fixed synthetic JWT key. The registry checks new registration,
legacy login without rewriting its hash, wrong password denial, forgot/reset,
weak/reused/expired tokens, and another tenant's unchanged credentials.
TessTOC checks legacy login, cost 12, denied unauthorized/non-admin resets,
authorized admin reset and old/new password behavior, using only its own
synthetic trainers. Original actor credentials/role are restored after the check.
No such password-reset checks run against production accounts.

Before publication, back up apps/config/all four databases on the Russian server
and verify restore. Publish sequentially with existing rollback, idle-game,
.env/schema and immutable-asset guards. Check all projects, actual installed
packages, security headers, fonts/layout, and one own tesstech.ru form and mailbox
delivery. Existing hashes require no migration or forced user password reset.
